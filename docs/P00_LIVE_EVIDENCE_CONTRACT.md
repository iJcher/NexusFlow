# P00 独立真实收件证据关联门禁

真实邮件可先发送一次，再由用户在本地终端隐式输入实际收件 OTP 与 Message-ID，完成真实 API 登录、身份检查、退出及旧 token 拒绝访问。它不是自动读邮箱，也不是 Mailpit 收件。

`live-email.json` 保存脱敏 PASS 结果。主代理已在本轮实际核对用户完成操作与文件，并从随后冻结本地验收报告生成 `provenance.json`：真实结果文件字节 SHA-256、运行源码清单 SHA-256，不含秘密。该元数据是显式人工核对记录，不是密码学签名或第三方投递证明；有权限修改本地验收目录的人仍在可信操作员边界内。

统一入口：

```powershell
pnpm verify:stage -- P00 --local --live-evidence=artifacts/acceptance/P00/live-mail-1791534798474
```

导入模式不加载 `.env.live`、不发邮件、不读取 OTP、不重新登录；先实际重跑本地单测/API/浏览器、迁移/构建/lint，再校验脱敏证据及绑定的源码。只允许 P00，不能与 `--live` 同用。导入不会原地改写历史报告。

文件必须为普通非符号链接、最大 64KiB。证据严格字段白名单、指定人工模式、登录/注销成功、两个 canonical SHA-256；发送→收件→认证时间单调、不能未来、最长20分钟，7天后不能复用。provenance 必须精确绑定原文件字节，并完整、排序、无重复地匹配当前运行源码清单。

源码范围：全部后端 src/prisma、全部前端 src、根/两端 package.json 与 lockfile、实际 live-email-smoke.ts。测试/文档/纯证据门禁变化可以重新测试后复用；运行源码变化则拒绝导入，需要查明变化是否影响真实验证并重新取得适用证据，不能直接改 provenance 让门禁变绿。

独立子代理在临时目录验证缺失/伪造/篡改/过期/源码变化均不能 PASS，以及合法证据只读导入零发信。P00 只有本地和真实证据同时 PASS 才达到完整门禁；P01/P02 与后续阶段仍按各自合同验收。
